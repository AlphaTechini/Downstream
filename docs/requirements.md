# Downstream: requirements

Written 2026-10-22. Deadline: **Tue 2026-10-27 13:00 UTC (14:00 Lagos)**. Priorities use
MUST / SHOULD / COULD. Every requirement has a way to check it. A requirement is only
"done" when the check has been run and its output is committed under `evidence/`.

Design context is in [details.md](details.md); the reviewer and maintainer experience is in
[userflow.md](userflow.md).

## 2. Functional requirements

### 2.1 Trigger and visibility

| ID | Pri | Requirement | Check |
|---|---|---|---|
| FR-01 | MUST | One mention on a merge request plans, runs, investigates and reports. No second command is needed for the first report. | Evidence run: single mention, final report note present. |
| FR-02 | MUST | The first thing posted is an acknowledgement note naming the base and head commits. | Note in the evidence run. |
| FR-03 | MUST | Every stage posts a note (journeys, report), because the session UI shows only "Ran tool". | Evidence run shows notes in order. |
| FR-04 | MUST | A final merge request note is posted even when the run fails, including the failing step and the engine's error text. | Fault-injection run (break the build deliberately), note present. |

### 2.2 Journeys

| ID | Pri | Requirement | Check |
|---|---|---|---|
| FR-10 | MUST | The agent generates 3 to 6 journeys from the diff and the route table, as JSON that validates against the engine's schema. | Engine rejects a malformed file; unit test in `engine/`. |
| FR-11 | MUST | Journeys run through the changed route and the routes in its blast radius. At least one journey avoids the changed route. | `scan.json` and `journeys.json` of the evidence run. |
| FR-12 | MUST | Every journey is validated on the baseline first. A journey failing on baseline is discarded and listed. | Test with a deliberately broken journey. |
| FR-13 | MUST | The reviewer sees a plain-English summary of each journey before the numbers, following `agentnotes.md`. | "Journeys added" note in the evidence run. |
| FR-14 | MUST | Journeys use only the app's own API. No fixture that bypasses it. Targets only `127.0.0.1`. | Engine schema rejects absolute URLs; test. |

### 2.3 Measurement

| ID | Pri | Requirement | Check |
|---|---|---|---|
| FR-20 | MUST | Run baseline twice (B1, B2) and the candidate once (C), sequentially, in the order B1, C, B2. | `run.json` records the order and timestamps. |
| FR-21 | MUST | Per step: count, failures, p50, p95, mean. Per run: app CPU seconds and peak RSS. | `run.json` fields. |
| FR-22 | MUST | Noise band per metric from B1 versus B2. | `run.json` fields. |
| FR-23 | MUST | Classify each finding as regression, trade-off or noise using the rules in `agentnotes.md`. | Unit tests with synthetic inputs for each class. |
| FR-24 | SHOULD | Report database time when the target exposes it; otherwise print "DB time: not measured". | Report text in the evidence run. |
| FR-25 | MUST | No figure appears in a note unless it is in `run.json`. | Report generated by script; reviewed in the evidence run. |

### 2.4 Report and issues

| ID | Pri | Requirement | Check |
|---|---|---|---|
| FR-30 | MUST | Tables and Mermaid are rendered by the engine, not the model. | Code path in `engine/report`; model has no table-writing step. |
| FR-31 | MUST | The report lists discarded journeys, what was not measured, and that a three-run design gives no confidence interval. | Report text. |
| FR-32 | MUST | One issue per regression: repro, figures with noise band, likely cause, numbered fix options, reply instructions, hidden marker. | Issue in the evidence run. **T-08** |
| FR-33 | MUST | The user who started the run is tagged in each issue. | Issue body; notification observed. **T-08** |
| FR-34 | MUST | Trade-offs become a question on the merge request, not an issue. | Evidence run with a seeded trade-off. |
| FR-35 | SHOULD | If issue creation does not work from a custom flow, fall back to merge request threads, one per regression, and say so in the README. | Decided after T-08. |
| FR-36 | COULD | Publish a before/after page with GitLab Pages when allowed; otherwise post in the merge request. | **T-13** |

### 2.5 Fix loop

| ID | Pri | Requirement | Check |
|---|---|---|---|
| FR-40 | MUST | `@<handle> fix option N` in an issue thread selects numbered option N and reruns the same journey. State comes from the issue body and its marker only. | Evidence run: reply, delta note. **T-09** |
| FR-41 | MUST | If option N cannot be applied by the flow, it says so and stops. It never claims a fix it did not apply. | Test with a non-applicable option. |
| FR-42 | SHOULD | Apply the change on the merge request source branch. Fallback: post a unified diff for a human to apply. | **T-10** |
| FR-43 | SHOULD | `@<handle> verify` after merge reruns the stored journeys on the merge commit against the pre-merge target commit. | Evidence run. |
| FR-44 | COULD | `@<handle> correction: <text>` makes the flow redo a step with the maintainer's correction. | Demo only if time allows. |

## 7. Risks

| Risk | Likelihood | Effect | Response |
|---|---|---|---|
| A custom flow cannot create issues or commit (T-08, T-10 fail). | Medium | Loses the issue and fix-loop story | Fall back to merge request threads and diffs in notes (FR-35, FR-42). Say so. |
| Credits run out before enough evidence runs. | Unknown (T-11) | Fewer runs | Measure early; cap runs; prioritise the five required. |
| Demo target does not build in the sandbox. | Medium | Lost day | Decide by Friday; prefer the purpose-built small API if the first candidate fails. |
| Baseline noise on a shared runner is higher than the thresholds allow. | Medium | False regressions or none | Widen thresholds with evidence; report noise honestly. |
| The first probe stopped after one action; a longer chain could stop early again. | Low-medium | Incomplete runs | Firm prompt, final-note rule (FR-04), short chains between notes. |
| Judges cannot trigger the flow unless added as project members. | Likely (C-07) | Cannot reproduce live | Committed evidence runs and the recorded demo. State it. |
| The regression looks staged. | Medium | Credibility | Label it as planted, link the commit, show the engine also reports a clean change as clean. |
